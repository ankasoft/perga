# Packaging

What is here, and what a packager needs to know.

## Before anything else

perga is dual licensed `MIT OR Apache-2.0`. **Every package must install both
licence files.** The artefacts here do; match them if you write another. See
[`../docs/licensing.md`](../docs/licensing.md).

Every package must also install the man page and the shell completions.
Packagers ask for these first, and retrofitting them later is tedious. They are
generated by running the binary (`perga --generate-man`,
`perga --generate-completions bash|zsh|fish`) and are shipped pre-generated in
every release tarball, so a package built from a tarball installs the files and
a package built from source runs the freshly built binary.

## `PKGBUILD`: Arch, `perga-bin`

Downloads the release tarball for the host architecture and installs the
binary, the man page, the three completion files, both licences, and the
README.

**Per release, update two things:**

1. `pkgver`, to the version being packaged.
2. `sha256sums_x86_64` and `sha256sums_aarch64`, from the `.sha256` files
   attached to the GitHub Release:

   ```sh
   v=0.1.0
   base=https://github.com/ankasoft/perga/releases/download/v$v
   for arch in x86_64 aarch64; do
     curl -sL "$base/perga-$arch-unknown-linux-musl.tar.xz.sha256"
   done
   ```

Then `updpkgsums` if you prefer, `makepkg --printsrcinfo > .SRCINFO`, and push.

`options=('!strip')` is set because the release profile already strips; running
`strip` again on a musl static binary buys nothing and has been known to break
one.

## Debian and RPM

The metadata lives in `Cargo.toml`, under `[package.metadata.deb]` and
`[package.metadata.generate-rpm]`, so the asset lists cannot drift from the
package version.

```sh
cargo install cargo-deb cargo-generate-rpm

# Both expect a release build and the generated auxiliary files. The script is
# the same one `dist` runs while building a release.
bash packaging/generate-assets.sh

cargo deb
cargo generate-rpm
```

The asset lists reference `target/assets/`, so `generate-assets.sh` is not
optional.

## What is deliberately not here

**Snap and Flatpak.** Their default confinement prevents reading arbitrary
directories, which is the entire function of this application. `classic`
confinement would work and requires a review process that file-browsing tools
generally do not pass. A user who wants a sandboxed Markdown browser is better
served by a different tool than by one that cannot open their notes.

**A `perga` source package for the AUR.** `perga-bin` is the maintained one.
Nothing stops someone writing a source PKGBUILD; it is not maintained here.
